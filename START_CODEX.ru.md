# Запуск Search Compare через Codex

Подключение готово. API-ключ не нужен: используется сохранённый вход Codex через ChatGPT. Запуски расходуют доступный лимит твоего аккаунта. Если доступа к модели или лимита нет, стенд сохранит ошибку и остановит соответствующий этап.

В этой рабочей папке уже создан `configs/codex.json`. В нём выбрана модель `gpt-5.6-terra` из твоих локальных настроек Codex. Проверка трёх реальных запросов успешно завершилась; её результат находится в `runs/codex-connection-passed/report.md`.

## Первый эксперимент

Открой терминал VS Code в папке `search_compare`. Убедись, что Docker запущен. Посмотри настройки эксперимента:

```sh
.venv/bin/python -m searchlab plan --config configs/codex.json
```

Затем запусти:

```sh
.venv/bin/python -m searchlab run --config configs/codex.json --live
```

Это реальный эксперимент, а не режим со скриптовыми ответами. Стенд запускает baseline, поиск AFlow и поиск ADAS, сохраняет выбранные агенты и проверяет их на отдельных тестовых задачах. В конце он напечатает путь к папке результатов. Открой в ней `report.html` или `results.csv`.

Текущая конфигурация — небольшой пилот: GSM8K, одно публичное обучающее задание, два задания для выбора агента, три тестовых задания, один seed, одна итерация поиска. Этого достаточно для проверки полного процесса, но мало для вывода о превосходстве одного метода.

Для каждого метода поиска установлены ограничения: 80 запусков Codex, 500 000 токенов и 20 минут. Для baseline validation и каждого финального тестирования — 120 запусков, 500 000 токенов и 30 минут. Это верхние пределы; обычно запуск остановится раньше. Суммарный предел текущей конфигурации — 640 запусков, а не 80: лимиты применяются отдельно к этапам. Проверь значения перед запуском. Если ограничения не позволили завершить тестирование, итоговая оценка не публикуется.

## Какие метрики сохраняются

- Качество решения задач: точность, DROP F1, прохождение тестов кода или метрики AgentDojo.
- Изменение качества относительно baseline, результаты по каждому seed, среднее и стандартное отклонение.
- Количество запусков Codex отдельно для поиска и финального выполнения.
- Входные, выходные и кэшированные входные токены.
- Время поиска, время выполнения задач, ошибки и статус завершения.
- История кандидатов, сохранённый финальный агент, ответы и события каждого запуска Codex.

Стоимость подписочного вызова в долларах Codex не сообщает. В JSON она равна `null`, в отчёте — `unknown`. Нулевую стоимость стенд не приписывает. Если запуск прерван и полного расхода токенов нет, выставляется `token_usage_complete: false`; известные числа не считаются полным расходом.

## Добавление задач и повторов

Чтобы создать отдельную конфигурацию для нескольких типов задач:

```sh
.venv/bin/python -m searchlab init-codex --output configs/codex-multi.json --benchmarks gsm8k drop mbpp agentdojo_workspace
```

Команда не вызывает модель. Она создаёт небольшие наборы из уже подготовленных данных и новую конфигурацию, не меняя существующую. Увеличь `seeds`, `search.iterations`, размеры наборов и лимиты для содержательного исследования. В `datasets` можно указать полные подготовленные файлы `data/gsm8k.json`, `data/drop.json`, `data/mbpp.json` и `data/agentdojo_workspace.json`.

Повторная проверка подключения выполняет три реальных запроса:

```sh
.venv/bin/python -m searchlab check-codex --config configs/codex.json
```

## Как обеспечивается сопоставимость

Один запрос стенда соответствует новому `codex exec`: история предыдущего чата не используется. Пользовательские настройки, инструкции проекта, подключённые приложения, веб-поиск и инструменты командной строки отключены для этих запусков. Инструменты AgentDojo передаются как описания; Codex возвращает запрос инструмента, а исполняет его сам стенд. Неожиданный вызов собственного инструмента Codex делает запуск недействительным.

Температура и seed генерации через CLI не задаются; это отмечено в журнале. Seed эксперимента управляет случайностью алгоритма поиска, но не гарантирует одинаковые ответы модели. Одинаковые настройки Codex применяются к обоим методам.

Лимит токенов проверяется между запусками: один вызов может его превысить, после чего текущая оценка прерывается. Число запусков и время ограничиваются отдельно. Codex может выполнять внутренние повторы сетевых запросов, поэтому число запусков CLI не равно числу HTTP-запросов к модели. Исходные события расхода сохранены в `codex_events/`.
